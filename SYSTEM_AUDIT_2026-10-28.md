# Общий аудит системы — 28 октября 2026

## Итог

**65/100 — рабочая локальная система с существенными ограничениями надёжности.** Оценка служит приоритизации исправлений, а не является вероятностью отказа. До открытия доступа извне необходимо включить авторизацию и выделить ключ шифрования. Зелёные контейнеры и тесты не означают завершённую проверку всех пользовательских сценариев.

Аудит охватил конфигурацию запуска, HTTP API, базу и очереди, обработчики, AI, медиа, авторизацию, резервное копирование, релизную копию и текущие результаты интеграций. Публикации, подтверждения источников и настройки в ходе аудита не менялись. Внешние сообщения не отправлялись.

## Подтверждённые проблемы

### 1. P1 — API в текущем режиме не требует авторизации

Runtime: APP_ENV=development; OPERATOR_TOKEN отсутствует. Без заголовка оператора GET `/api/vacancies?limit=1` и `/api/threads/quality-guard` вернули HTTP 200. `backend/app/security.py:39` разрешает запросы без ключа в development. Тот же общий dependency защищает и изменяющие API, поэтому при этой конфигурации он не аутентифицирует вызывающего.

Порты приложения опубликованы только на 127.0.0.1, что ограничивает доступ с других машин. Это не защита от других локальных процессов/пользователей и не настройка для публичного сервера. Нужны OPERATOR_TOKEN, проверка негативных сценариев и явный режим эксплуатации. Запросы на изменение без ключа в рабочую систему при аудите не отправлялись.

### 2. P1 — нет отдельного ключа шифрования Threads

Runtime: THREADS_TOKEN_KEY отсутствует. `backend/app/threads_client.py:118` читает токены через резервный ключ LITELLM_MASTER_KEY. Токены зашифрованы, но их хранение связано с секретом другой подсистемы. Замена ключа шлюза без миграции может лишить приложение доступа к сохранённым токенам. Нужен отдельный ключ с проверенной миграцией и сохранением возможности восстановления.

### 3. P1 — проверка ответов на комментарии пропускает неподтверждённые факты

`backend/app/ai.py:520` передаёт факты модели, но callback валидатора в `:553` проверяет общий формат через validate_generated_post. Сопоставления ставки с фактами вакансии нет. `worker/publishing.py:377` проверяет одобрение, риск и лимиты ответа, но не его условия по вакансии.

Воспроизведено изолированно: при входном факте «30,50 zł/год netto» подставленный ответ «999 zł/год netto» прошёл callback. Реальная модель и Threads не вызывались. Это не доказательство уже отправленного неверного ответа. Сейчас ответ требует одобрения человеком. Нужна проверка фактов ответа при подготовке и перед отправкой, с тестами на изменение вакансии.

### 4. P1 — ежедневное резервное копирование проекта не зарегистрировано

В Планировщике Windows не найдена задача `Threads Recruitment - DB Backup`. Последние архивы проекта: 28 октября, 26 октября, 9 октября — сами по себе они не доказывают регулярное ежедневное копирование.

Дополнительно `scripts/schedule-backups.ps1:88` регистрирует запуск backup-db.ps1 вместо собственного режима -Run. Поэтому предусмотренные во вспомогательном скрипте вторичное копирование и очистка не исполняются; при передаче SecondaryPath аргументы передаются скрипту, который их не принимает. Get-TaskCommandRaw объявлен дважды (:50 и :96).

Нужно исправить команду задачи, зарегистрировать расписание, проверить журнал запуска и восстановление в отдельную временную БД. Свежая ручная копия существует; восстановление в этом аудите не выполнялось.

### 5. P1 — здоровье двух worker может показываться ошибочно

Оба worker пишут один Redis-ключ `threads:worker:heartbeat` и одну строку worker_heartbeat: `worker/main.py:117`. `worker/health.py:15` и `backend/app/api.py:215` читают общую отметку. Активный процесс может скрыть отсутствие heartbeat другого. Сейчас оба контейнера действительно работают; отказ для проверки не имитировался.

Нужны отдельные heartbeat по ролям и независимые признаки продвижения очередей.

### 6. P2 — одобрение неожиданно запускает публикацию

`backend/app/services.py:183`: при разрешении политики approve назначает отправку через минуту. Кнопка «Одобрить» поэтому одновременно подтверждает текст и запускает доставку. Нужны отдельные действия: одобрить, назначить время, отправить сейчас. Это существующее поведение, не ошибка часового пояса.

### 7. P2 — статус COMPLETED не показывает полезный результат агента

В базе найдены COMPLETED для SCOUT с нулём новых сигналов и REPLIER с нулём ответов. `AIService.draft_reply` возвращает None при HTTPException; `draft_replies` пропускает такой результат, а run_agent отмечает успешно вернувшийся запуск COMPLETED. Ноль может означать отсутствие работы, отказ проверки или ошибку модели — причины не разделены.

Нужны отдельные исходы NO_WORK, PARTIAL, FAILED и счётчики обработано/отклонено/ошибка.

### 8. P2 — один запрос интерфейса обходит общий API-клиент

`frontend/src/pages/AgentsPage.tsx:43` напрямую вызывает fetch('/api/threads/quality-guard') без заголовка оператора и скрывает ошибку. В нынешнем development без ключа запрос проходит. После включения OPERATOR_TOKEN блок диагностики перестанет загружаться. Нужны общий клиент и видимое состояние отказа.

### 9. P2 — включена настройка внешних комментариев без реализованной отправки

В runtime auto_external_comment=true. Supervisor вернул unsupported_external_comment_automation: безопасного пути отправки внешних комментариев нет. Настройка создаёт ожидание функции, которой нет. Нужны отключение недоступной опции или полноценная реализация с разрешениями и тестами.

### 10. P2 — ошибки задач смешивают сбои и нормальные отмены

FAILED содержит и сетевые ConnectError/Timeout, и Superseded by reschedule, и Replaced by explicit publish-now request, и возврат поста на подготовку. Общий счётчик ошибок завышает аварийность. Нужны CANCELLED/SUPERSEDED/BLOCKED или отдельная классификация причин.

### 11. P2 — текущую версию нельзя воспроизвести одним Git checkout

Рабочая копия содержит изменённые и неотслеживаемые исходники, включая новые модули и миграцию. Локальная ветка показывает ahead 22 относительно сохранённого origin/master; актуальное состояние удалённого сервера не проверялось. Нужны зафиксированный релиз, инструкция отката и проверка сборки с чистого checkout. Наличие локальных Docker-образов не заменяет сохранение исходников.
