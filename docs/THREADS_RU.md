# Подключение настоящего аккаунта Threads

[К полной настройке](SETUP_RU.md)

## Перед началом

Нужны ваш профиль Threads и доступ к Meta for Developers. Используются официальный Threads API и токен пользователя, а не пароль Threads. Подключение Instagram само по себе не подключает Threads.

Начните с отдельной базы для live. Существующие mock-аккаунты, посты и очередь не переносите в боевой запуск. Сохраните backup, если в базе уже есть нужные данные. Для нового независимого набора Docker volumes задайте другой `COMPOSE_PROJECT_NAME`; если старый проект ещё запущен, сначала остановите его или измените порты нового проекта. Не удаляйте volumes ради подключения аккаунта.

В приложении оставьте режим MANUAL и выключенную автоматизацию. Само `THREADS_MOCK_MODE=false` не разрешает агенту публиковать посты.

## 1. Создать приложение Meta

1. Откройте [Meta for Developers](https://developers.facebook.com/apps/), войдите под владельцем и создайте приложение с use case/product **Threads API**. Точные названия экранов определяет текущий кабинет Meta.
2. В настройках Threads найдите **Threads App ID** и **Threads App Secret**. Используйте реквизиты именно Threads-продукта, если кабинет показывает несколько наборов ID.
3. Добавьте свой Threads-профиль как тестировщика/пользователя с ролью приложения и примите приглашение там, где это предлагает Meta. Доступ приложения в development ограничен назначенными ролями и выданными правами.
4. Для подключения чужих пользователей могут потребоваться Live mode, App Review, проверка бизнеса, политика конфиденциальности и URL удаления данных. Эти требования проверяются в кабинете Meta; код проекта их не обходит.

## 2. Настроить разрешения

Текущий OAuth-клиент запрашивает список ниже. Включите нужные разрешения в продукте Meta и проверьте, что они действительно выданы токену.

| Разрешение | Для чего использует проект |
| --- | --- |
| `threads_basic` | Профиль и базовые данные |
| `threads_content_publish` | Публикация |
| `threads_read_replies` | Чтение ответов |
| `threads_manage_replies` | Работа с ответами |
| `threads_manage_insights` | Статистика |
| `threads_manage_mentions` | Упоминания |
| `threads_keyword_search` | Поиск публичных обсуждений |

Набор доступных функций зависит от прав. Отсутствие одного разрешения нельзя исправить автоперезапуском. Используйте раздел «Разрешения Threads» в приложении и `/api/threads/capabilities`. Для запроса расширенных прав есть [заготовка](meta-scopes-request.md), которую нужно адаптировать к своему приложению. Если Meta отклоняет запрашиваемый scope, проверьте его доступность и настройки продукта; не подменяйте реальную проверку фиктивным списком прав в базе.

## 3. Выбрать способ подключения

### Способ A: OAuth через приложение

Это основной способ: интерфейс открывает окно Meta, backend меняет code на токен, затем на долгоживущий токен и хранит его зашифрованным.

Для надёжного callback используйте HTTPS и зарегистрируйте **точно совпадающий URL**:

```dotenv
THREADS_APP_ID=YOUR_THREADS_APP_ID
THREADS_APP_SECRET=YOUR_PRIVATE_THREADS_APP_SECRET
THREADS_REDIRECT_URI=https://recruit.example.com/api/threads/oauth/callback
THREADS_MOCK_MODE=false
AUTO_POST=false
AUTO_REPLY=false
AUTO_EXTERNAL_COMMENT=false
```

`recruit.example.com` — пример, не готовый сервер. Настройте собственный домен и TLS reverse proxy к frontend, который уже проксирует `/api/` в backend. Все страницы UI и callback должны открываться в одном браузере через **один и тот же origin**. Проект связывает OAuth с cookie `threads_oauth_state`; начать на localhost и вернуться на другой домен нельзя — cookie не совпадёт, будет ошибка `state`.

В текущем Compose переменная `FRONTEND_URL` не передаётся автоматически из `.env`. Для внешнего адреса создайте локальный `compose.override.yaml`:

```yaml
services:
  backend:
    environment:
      FRONTEND_URL: https://recruit.example.com
```

Замените домен своим. Этот override не содержит секретов, но его адрес индивидуален для установки. `FRONTEND_URL` определяет, куда backend вернёт браузер после OAuth. Если меняете только `FRONTEND_PORT` для localhost, аналогично задайте актуальный `FRONTEND_URL`.

Перед внешним доступом установите сильный `OPERATOR_TOKEN`, TLS, ограничения сетевого доступа и защиту reverse proxy. Разрешите callback и webhook для провайдера; остальные API требуют операторский заголовок. Не выставляйте MySQL, Adminer, Redis, LiteLLM или Hermes наружу. Значения `http://localhost:8000/...` в `.env.example` — локальные заготовки, а не обещание приёма Meta. Публичный OAuth требует своей сетевой настройки.

Примените настройки:

```powershell
docker compose config --quiet
docker compose up -d --force-recreate backend worker worker-agents
```

Откройте приложение через настроенный HTTPS-домен → «Аккаунт Threads» → подключить. В окне Meta убедитесь, что выбран нужный профиль, подтвердите права и дождитесь возврата в приложение. Не перезапускайте backend посреди авторизации. `state` действует ограниченное время; при ошибке начните заново из интерфейса.

### Способ B: официальный токен для локального подключения

Если HTTPS/OAuth пока не настроен, текущий интерфейс имеет поле импорта токена на странице аккаунта Threads. Получите токен **своего** пользователя в официальном Threads token generator / инструментах приложения Meta, выберите нужные права и проверьте его в официальном debugger. Доступность генератора зависит от кабинета и роли пользователя.

Установите `THREADS_MOCK_MODE=false`, заполните реквизиты приложения и постоянный `THREADS_TOKEN_KEY`, пересоздайте backend и workers. Введите токен в поле подключения на локальной странице «Аккаунт Threads». Backend проверит профиль и publishing limit и сохранит зашифрованный токен. Не помещайте его в исходники или frontend ENV.

Этот путь не проверяет OAuth callback. Он также не гарантирует долгий срок действия: проверяйте expiry и повторно подключайте аккаунт при необходимости. `THREADS_ACCESS_TOKEN` — низкоуровневая настройка разработки, она не заменяет подключённую запись аккаунта в UI. Флаг `ALLOW_MANUAL_TOKEN_IMPORT` относится к отдельным маршрутам Instagram/TikTok; Threads имеет собственный endpoint `/api/threads/account/token`.

## 4. Проверить подключение

На странице аккаунта нажмите проверку. Или выполните `POST /api/threads/account/test` с `X-Operator-Token`, затем `GET /api/threads/account`.

Проверьте:

- username совпадает с ожидаемым человеком/организацией;
- аккаунт подключён, `mock_mode=false`;
- нет `BLOCKED`, ошибки токена или запрета публикации;
- разрешения и срок токена соответствуют вашим задачам;
- `/api/threads/capabilities` показывает доступность чтения, ответов и статистики;
- `/api/health` не выдаёт mock-состояние Threads. Недоступность другой интеграции анализируйте отдельно.

Подключённый профиль ещё не доказывает успешную публикацию. После проверки текста и явного решения владельца опубликуйте **один** пост вручную и найдите его на реальном профиле. Зафиксируйте ссылку; после timeout сначала проверьте профиль, чтобы не опубликовать дубль.

Для чтения ответов можно вызвать `POST /api/threads/community/sync` с операторским заголовком, затем проверить очередь и UI. Наличие прав не создаёт комментарии: нужны реальные ответы на посты вашего аккаунта.

## 5. Webhook — необязательно

Polling уже предусмотрен. Для webhook задайте случайный `THREADS_WEBHOOK_VERIFY_TOKEN` и в Meta зарегистрируйте `https://ВАШ_ДОМЕН/api/threads/webhook` с тем же verify token. Backend поддерживает GET challenge и проверку подписи POST через App Secret; уведомление ставит синхронизацию в очередь. Не путайте verify token, пользовательский access token и App Secret.

Проверьте доступность URL извне, TLS, поля подписки в кабинете Meta и запуск worker. Не считайте webhook обязательным условием первой ручной публикации.

## Ошибки

| Симптом | Что делать |
| --- | --- |
| Redirect URI mismatch | Сравнить схему, домен, порт, путь и завершающий slash в Meta и `.env` |
| `threads_error=state` | Начать и закончить на одном origin, разрешить cookie, начать OAuth заново |
| 401 приложения | Ввести правильный OPERATOR_TOKEN; это не ошибка Meta |
| Нет scope / permission denied | Проверить выданные права, роль тестировщика и App Review |
| Токен истёк или отозван | Подключить профиль заново, не публиковать повторно вслепую |
| `BLOCKED` / app blocked | Проверить ограничения Meta, код ошибки и trace ID; перезапуск не снимает блокировку |
| Нет статистики / упоминаний | Проверить соответствующий scope и наличие данных |

Не переключайте работающую live-базу обратно в mock ради устранения OAuth-ошибки: это смешивает данные. Остановите автоматизацию и диагностируйте причину.

Источники: [Meta Threads documentation](https://developers.facebook.com/docs/threads/), [официальная коллекция Meta Threads API](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api). Во время подготовки прямые страницы Meta отвечали ограничением доступа; точные требования кабинета и доступность scopes нужно проверить в своём приложении. Локальные пути и поведение выше сверены с `threads_client.py`, `security.py` и `routers/accounts_media.py`.
