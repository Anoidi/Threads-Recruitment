# Порядок установки для агента

Это рабочий runbook к [заданию владельца](AGENT_PROMPT_RU.md), а не разрешение на публикации. Выполняйте уже согласованную установку до проверяемого результата; не останавливайтесь на плане.

## 1. Осмотр

Проверьте `git --version`, `docker version`, `docker compose version`, `docker info`, ОС, память и занятые порты. Команды ниже рассчитаны на PowerShell/Windows; на другой ОС адаптируйте пути и Docker host access. При необходимости установки Docker используйте официальный источник, отдельно сообщите о требуемой перезагрузке/WSL2. Не запускайте скачанный скрипт без просмотра.

Если папка уже существует, проверьте `git status --short` и remote. Не клонируйте поверх проекта и не выполняйте reset/clean. Для нового компьютера:

```powershell
git clone https://github.com/Anoidi/Threads-Recruitment.git
cd Threads-Recruitment
git rev-parse HEAD
```

Прочитайте `.env.example`, `docker-compose.yml`, `backend/app/config.py`, `litellm/config.yaml`, `backend/app/security.py`. Спросите только недостающие настройки: облако/локальная модель, нужные интеграции, источник вакансий, существующие live-данные. Не требуйте все ключи до запуска mock.

## 2. Подготовка ENV

Создайте `.env` **только если её ещё нет**. Генерируйте секреты криптографическим генератором и записывайте прямо в локальный файл через скрипт/редактор без stdout и transcript. Для новых установок нужны разные случайные значения как минимум для:

- MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD;
- LITELLM_MASTER_KEY, HERMES_API_KEY, OPERATOR_TOKEN;
- THREADS_TOKEN_KEY, SOCIAL_TOKEN_KEY — постоянные отдельные источники ключей шифрования.

Код выводит Fernet-ключ из строкового секрета через SHA256; для последних двух полей подходят длинные случайные строки или сгенерированный Fernet key. Не заменяйте существующие ключи ради «улучшения» — потребуется миграция. DATABASE_URL должен использовать пароль MYSQL_USER, не root. Пароль token_urlsafe удобен без URL-экранирования; для других форматов экранируйте зарезервированные символы URL. Если редактируете `.env` скриптом, сохраняйте UTF-8 без BOM и права доступа.

Начальные mock-флаги — как в [установке](../INSTALL_RU.md). TELEGRAM_CHANNEL и TELEGRAM_BOT_TOKEN оставьте пустыми до отдельного подключения: mock-флаги Threads/AI не отключают реальный Telegram polling. Не переносите чужой username канала из шаблона.

## 3. Поднять и проверить mock

```powershell
docker compose config --quiet
.\scripts\validate-infrastructure.ps1
docker compose up -d --build
docker compose ps
Invoke-RestMethod http://localhost:8000/api/health
Invoke-WebRequest http://localhost:3000/healthz
```

При нестандартных портах подставьте значения владельца. Проверьте операторский доступ через UI, используйте токен локально и не возвращайте его в отчёте. Создайте/проверьте тестовый сценарий только в mock-базе. Не открывайте публичный доступ ради первоначальной проверки.

Успех этапа: обязательные контейнеры работают, миграции прошли, frontend и backend отвечают, UI авторизуется. Ошибка одного optional-сервиса не должна приводить к стиранию базы или установке всех optional-сервисов.

## 4. Настроить AI

Следуйте [AI_RU.md](AI_RU.md). Подставьте реальные ID доступных моделей. В основном YAML маршруты читают `OMNIROUTE_*`; ключ, записанный только в OPENAI_API_KEY/OPENROUTER_API_KEY, их не перенастраивает. Для облака без Ollama отключите неработающий локальный fallback в своей конфигурации либо явно оставьте его непроверенным.

Пересоздайте litellm, backend, worker, worker-agents. Выполните один короткий запрос к `free-default`, затем один черновик с проверкой языка/фактов/JSON. Полный `test_litellm.py` не нужен по умолчанию: он делает много запросов и проверяет local. Не объявляйте AI проверенным по одному `/health/liveliness`.

## 5. Подключить источники и аккаунты

- [Telegram](TELEGRAM_RU.md): владелец создаёт бота и добавляет его в публичный канал. Проверяйте `getMe`/наличие webhook без вывода токена. Для приёмки дождитесь новой реальной вакансии. Не забирайте updates вторым polling-клиентом.
- [Threads](THREADS_RU.md): отдельная live-база, реквизиты Meta, права, постоянный encryption key. OAuth требует одинакового origin старта и callback; настройте FRONTEND_URL через Compose override. При локальном импорте официального токена отметьте OAuth как непроверенный.
- [Optional](OPTIONAL_RU.md): только выбранные владельцем интеграции. У Instagram/TikTok здесь нет законченного планировщика публикаций.

Владелец проходит OAuth/MFA и вводит приватные реквизиты в локальное хранилище. Пока он выполняет свои шаги, продолжайте независимую работу. Если он уже дал разрешение на определённое действие, не запрашивайте его повторно.

## 6. Передать работающую установку

Покажите интерфейс, вакансию и черновик, параметры времени, контакт, QA и политику MANUAL. Объясните остановку исполнителей и backup по [OPERATIONS_RU.md](OPERATIONS_RU.md). Не переводите проект в AUTO, не отправляйте тестовые сообщения и не создавайте реальные посты как неявную часть установки.

Отчёт должен содержать:

| Поле | Содержание |
| --- | --- |
| Установка | Путь, remote, commit, ОС, версия Docker |
| Доступ | URL интерфейса и API без токенов |
| AI | mock/configured/verified live/blocked, модель и реальная проверка |
| Threads | username, mock/live, scopes/expiry, проверка API; факт публикации отдельно |
| Telegram | bot username, канал, webhook/polling, факт импорта новой записи |
| Optional | enabled/disabled/blocked и проверенная возможность |
| Автоматизация | mode, emergency stop, лимиты |
| Данные | Где backup и где владелец хранит ключи, без самих секретов |
| Остаток | Конкретный шаг владельца или внешняя блокировка |

Если не хватает разрешений Meta или машина не тянет модель, сохраните исправную базовую установку и укажите блокировку. Не подменяйте проблему фиктивными статусами или отключением проверок.
