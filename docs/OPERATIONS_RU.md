# Работа, проверки и обслуживание

[К полной настройке](SETUP_RU.md)

## Первый рабочий сценарий

1. В настройках укажите язык, часовой пояс, контакт рекрутера и ограничения тем. Заполните достоверные условия вакансии: город, оплату, график, договор, жильё и транспорт, если они известны.
2. Проверьте исходный источник и подтвердите актуальность вакансии в интерфейсе. Импорт из Telegram и уверенный текст AI не являются подтверждением фактов.
3. Сгенерируйте черновик, проверьте язык, условия, контакт и ограничения. Если model QA отклоняет текст, исправьте причину, а не отметку результата в базе.
4. Проверьте календарь, часовой пояс `APP_TIMEZONE` и политику MANUAL. Одобрите текст и решите, публиковать ли его. Агент установки не принимает это решение за владельца.
5. После первой ручной публикации найдите пост на реальном профиле и сохраните permalink. Только затем обсуждайте расписание и автоматизацию.

## Автономность

Политика хранится в базе и проверяется сервером перед внешним действием. Откройте соответствующий раздел UI или `GET /api/threads/autonomy`. Проверьте `mode`, `emergency_stop`, `limits`, allowlists и `auto_blockers`.

Смена `.env`-флагов сама по себе не заменяет политику базы. Не включайте AUTO обходом проверки свежести и QA. Кандидатский сигнал — ещё не контакт; этапы воронки меняются человеком после проверки и согласия.

Для экстренной остановки используйте emergency stop в политике. Если UI недоступен, остановите исполнителей:

```powershell
docker compose stop worker worker-agents
```

Это не удаляет задания; после запуска очереди могут продолжиться. Сначала проверьте политику и уже выполненные действия, затем возобновляйте работу. При неясном исходе публикации сначала проверьте платформу, не нажимайте «повторить» вслепую.

## Проверки без внешних действий

```powershell
docker compose config --quiet
.\scripts\validate-infrastructure.ps1
docker compose ps
Invoke-RestMethod http://localhost:8000/api/health
Invoke-WebRequest http://localhost:3000/healthz
docker compose logs --tail 80 backend worker worker-agents
```

Не публикуйте полный `docker compose config` — он может содержать раскрытые значения окружения. Проверяйте `--quiet` или выводите только нужные несекретные поля. Health/liveliness подтверждает доступность процесса, но не права аккаунта и не качество AI. Состояния mock и optional disabled не равны проверенному live.

## Резервные копии

```powershell
.\scripts\backup-db.ps1
.\scripts\backup-media.ps1
```

Сохраните backup базы и медиа отдельно от компьютера. Секреты `.env` и ключи шифрования храните в защищённом хранилище: без прежнего ключа токены из backup могут не расшифроваться. Hermes имеет отдельный volume и требует отдельного сохранения, если используется.

Восстановление перезаписывает целевую базу. Прочитайте `scripts/restore-db.ps1` и используйте его обязательные параметры `-BackupFile`, `-ConfirmDatabase`, `-ConfirmRestore` только после проверки имени базы и явного решения владельца. Сначала отработайте восстановление в отдельной тестовой базе. Не используйте `docker compose down -v` как средство ремонта.

## Обновление

Сохраните изменения конфигурации и backup. Просмотрите изменения репозитория, затем обновляйте только чистую или отдельно сохранённую копию:

```powershell
git status --short
git pull --ff-only
docker compose up -d --build
docker compose ps
```

Миграции выполняются при старте backend. При их ошибке не стирайте базу: сохраните сообщение, проверьте версию и backup. Обновление кода, образов и схемы может требовать согласованного отката, а не только `git checkout`.

## Частые проблемы

| Проблема | Что проверить |
| --- | --- |
| Docker не отвечает | Docker Desktop запущен, WSL2 работает, `docker info` успешен |
| Порт занят | Выберите свободный порт в `.env`, обновите URL и FRONTEND_URL при необходимости |
| MySQL отвергает новый пароль | Существующий volume сохраняет старого пользователя; ENV не меняет пароль созданной БД |
| UI запрашивает токен снова | OPERATOR_TOKEN совпадает с backend, браузерный сеанс актуален |
| После ENV-правки ничего не поменялось | `up -d --force-recreate`, а не `restart`; нужные сервисы пересозданы |
| Очередь стоит | worker и worker-agents, Redis/MySQL, логи и причины отклонения |
| Черновик не публикуется | Решение QA, актуальность источника, режим, emergency stop, токен, scopes и лимиты |
| Сгенерированный пост выдумывает факты | Исправить исходные поля, выбрать подходящую модель, пройти QA повторно |

Для обращения за помощью отправляйте версии Docker/ОС, commit, имена сервисов, статус и очищенную ошибку. Не отправляйте `.env`, дамп базы, токены, полные HTTP URL Telegram или персональные данные кандидатов.
