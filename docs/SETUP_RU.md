# Полная настройка Threads Recruitment Manager

Руководство для нового компьютера. Проверено по коду репозитория 2 ноября 2026 года. Названия разделов кабинетов провайдеров могут меняться. Реальное подключение подтверждается проверкой вашего аккаунта, а не наличием переменной в `.env`.

## Маршрут установки

1. Выполните [первую установку](../INSTALL_RU.md): Docker, секреты, запуск в mock.
2. Настройте [AI](AI_RU.md): облачный провайдер либо локальная Ollama.
3. Подключите [Telegram](TELEGRAM_RU.md), если вакансии поступают из вашего канала.
4. Подключите [Threads](THREADS_RU.md): приложение Meta, разрешения, OAuth или импорт официального токена.
5. Заполните условия вакансий и контакт, проверьте черновик. Публикуйте первый пост вручную только после своего решения.
6. При необходимости настройте [Instagram, TikTok, ComfyUI и Hermes](OPTIONAL_RU.md).
7. Настройте [резервное копирование и обслуживание](OPERATIONS_RU.md).

Для установки с помощником передайте агенту [готовое задание](AGENT_PROMPT_RU.md). Сам агент должен прочитать [AGENTS.md](../AGENTS.md) и [порядок настройки](AGENT_SETUP_RU.md).

## Что требуется для каждой функции

| Функция | Что нужно | Как проверить |
| --- | --- | --- |
| Интерфейс, вакансии, тестовые черновики | Docker, заполненный `.env` | Открывается UI, health и контейнеры работают |
| Настоящая генерация | Доступная модель и маршрут LiteLLM | Непустой ответ модели и черновик из приложения |
| Threads | Профиль Threads, приложение Meta, разрешения и токен | Проверка аккаунта показывает нужный профиль и разрешения |
| Telegram | Собственный бот, публичный канал с username и доступ администратора | Новая вакансия канала появилась в приложении |
| Instagram / TikTok | Приложения соответствующих платформ, OAuth | Проверка профиля; это не подтверждение автопубликации |
| Изображения | Отдельный ComfyUI, совместимые веса и API workflow | Создан реальный файл, а не mock-результат |
| Hermes | Необязательный профиль Docker и доступная модель | Сервис запущен, агентная задача завершена |

## Что не нужно включать сразу

Оставьте `AUTO_POST=false`, `AUTO_REPLY=false`, `AUTO_EXTERNAL_COMMENT=false`. В базе есть отдельная политика автономности: ENV-флаги не заменяют выбор режима в приложении. Начните с MANUAL и проверьте `/api/threads/autonomy`.

Не переносите рабочую `.env` автора проекта. Создайте свою из `.env.example`, замените адрес канала `TELEGRAM_CHANNEL` на свой или оставьте пустым. Локальный OmniRoute из шаблона не устанавливается вместе с проектом.

После изменения `.env` обычный `docker compose restart` не применяет новые переменные. Используйте `docker compose up -d --force-recreate` с нужными сервисами. После изменения frontend build-переменных требуется пересборка frontend.

## Доступ к API

Интерфейс запрашивает `OPERATOR_TOKEN` из `.env`. Для защищённых API-запросов нужен заголовок `X-Operator-Token`. Исключения: health, webhook и OAuth callback. В Swagger автоматическая передача этого нестандартного заголовка может отсутствовать; пользуйтесь интерфейсом или клиентом HTTP.

Пример для PowerShell 7 без сохранения секрета в истории команды:

```powershell
$operatorSecret = Read-Host 'OPERATOR_TOKEN из вашей .env' -AsSecureString
$operatorCredential = [PSCredential]::new('operator', $operatorSecret)
$operatorHeaders = @{ 'X-Operator-Token' = $operatorCredential.GetNetworkCredential().Password }
Invoke-RestMethod http://localhost:8000/api/threads/account -Headers $operatorHeaders
Remove-Variable operatorSecret, operatorCredential, operatorHeaders
```

Не копируйте токены в сообщения агенту, issues, скриншоты или `VITE_*`. Агент может проверять наличие значения и результат запроса, не выводя секрет.
